## Phase 2 trial — video FPS detection

Implemented lazy MediaInfo.js worker detection with a 15-second timeout and 32 MiB
read budget. Explicit constant-rate metadata supplies an editable suggestion;
unknown/failing metadata uses manual input, and variable-rate video requires another
file. The confirmation dialog blocks tracking; images bypass it. Restored projects
default to saved FPS, show mismatches and require acknowledgment for edits. Stored
measurement timestamps remain unchanged. Sidebar Review frame rate uses this same
dialog. See ADR 008 for lifecycle, performance and compatibility decisions.

73 tests, lint, build and whitespace checks pass. Real metadata checks: generated
CFR clip → 29.97002997002997 FPS; VFR clip → variable; SpaceX sample → 30 FPS.
SpaceX inspection read 1.5 MiB from a 15.7 MB file in about 9 ms after initialization
in Node; this is not browser latency evidence. The production worker/WASM was also
executed against both generated clips with simulated browser globals and local fetch.
WASM is about 2.6 MB (981 kB gzipped), loaded only for video detection. Vite warns
about the library's unused fallback WASM URL; the explicit emitted asset URL was
verified by executing the built worker. Prior bundle-size/Browserslist warnings remain.

Owner browser review remains pending. No deployment. The remaining scale/pixel/axes
portion of the earlier Phase 2 plan has not been implemented in this timing trial.

## FPS usability revision

Owner testing found that VFR rejection excluded ordinary classroom videos. Removed
the block. The detector retains reported VFR average FPS and the dialog offers
30/60/120/240 with the closest familiar value selected within 10%. Accepting that
choice retains exact detected timing; another preset overrides it. Other permits
24/25 and custom values. Missing metadata uses an explicitly labeled 30 FPS default.
Saved timing is preserved and protected against unacknowledged edits. Both languages
and the sidebar show familiar common-rate labels; no decimal typing is required.
Original point timestamps remain unchanged. Exact frame-by-frame VFR seeking remains
a separate limitation, not a reason to reject the video.

Validation: 74 tests, lint, build and whitespace checks pass. Coverage includes VFR
average retention, common-rate grouping, unusual rates, explicit overrides, saved
timing, fallback and unblocked dialog rendering. Local app responds on port 5174.
Owner browser review is pending; existing build warnings remain.
