## Keyboard shortcuts for manual tracking (spec 22)

Owner approved a colleague's recommendation, including Backspace undo. Implemented
locally: Space records at the reticle and advances one frame (same routine as a
reticle tap); ← / → and `,` / `.` step frames through the frame-button routine;
Backspace removes the last point and returns to its frame. Outside manual tracking
Space plays/pauses; in automatic tracking Space and Backspace are inert.

Key/focus rules live in src/utils/trackerShortcuts.js; VideoCanvas owns one window
keydown listener. Keys are left alone in text/number fields, selects, menus,
dialogs, tab lists, tables, keyboard-focused controls, hidden Tracker view, open
welcome/FPS/distance dialogs and with Ctrl/Alt/Meta. A control left focused by a
mouse click is blurred so Space does not re-activate it. Tooltips and manual help
name the keys in EN/ES (new keySpace/keyBackspace translations).

Existing timelineTracking test now finds transport buttons by aria-label because
titles carry the key hint; its assertions are unchanged.

189 tests (11 new in tests/trackerShortcuts.test.js), lint, build and whitespace
checks pass. Component tests drive the real key handler with simulated video

### Shortcut correction after owner test

Owner reported no visible effect. Chromium was connected to the local dev server
and received the new code, so the page was current. Cause identified by code
reasoning (no browser trace): the "reached by keyboard" test used `:focus-visible`,
which browsers enable on a mouse-focused button once a key is pressed; focus
returns to the tracking button after choosing Manual tracking, so keys were
ignored. Replaced with recorded focus modality (createFocusModality). 190 tests,
lint, build and whitespace checks pass. Owner browser re-test pending.
